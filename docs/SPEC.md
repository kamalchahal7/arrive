# Arrive: build specification

> **Arrive: the immigrant's best friend.** Official government information, explained for newcomers in their own
> language, by text or voice, with a real person when they need one, and anonymized needs data that helps
> government serve them better.

This document is the source of truth for building Arrive. Build it in the phases in section 14. At the end of
each phase, stop, summarize what was built, list anything marked `[VERIFY: ...]`, list manual setup steps the
team must do (dashboards, keys, DNS), and wait for approval before continuing.

---

## 1. Context

### 1.1 The challenge
Hack the Hill Civic Technology Challenge: build something that brings government closer to people, or people
closer to government. The demo must clearly identify:

| Requirement | Arrive |
|---|---|
| People served | Newcomers to Canada, starting with refugee families and sponsored seniors in Ottawa facing language and technology barriers |
| Institutions involved | IRCC, CRA, Service Canada, ServiceOntario, City of Ottawa, government-funded settlement agencies |
| Interaction improved | Getting official information, knowing what to do and when, reaching a real person, and letting institutions see what newcomers struggle with |

Arrive works in both directions:
- **Government → people:** official information, personalized and in the person's language.
- **People → government:** anonymized needs data (top needs, knowledge gaps, confusing pages, language demand).

We are also competing for the **best user experience prize** (usability, interaction design, coherence, clarity,
basic accessibility; design must make the core function easier to use, not just prettier), and sponsor prizes
for Gemini, ElevenLabs, Tiger Data, Auth0, Vultr and GoDaddy Registry. Each must be used meaningfully.

### 1.2 Primary persona
**Amira**, 38, arrived in Ottawa from Syria three weeks ago as a permanent resident (resettled refugee) with two
children. Speaks Arabic, basic English. Has a smartphone shared with her family and limited data. Has never used
an AI assistant.

### 1.3 Secondary users
- **Settlement workers** at local agencies: receive handoffs, need fast context.
- **Government analysts**: see anonymized, aggregated needs to improve services and communication.

### 1.4 MVP scope
- City: Ottawa, Ontario.
- Statuses: `refugee_pr` (resettled refugee / permanent resident) and `international_student`. Structure the code
  so more statuses can be added (`asylum_claimant`, `economic_pr`, `family_class`, `temporary_worker`).
- Languages: English (`en`), French (`fr`), Arabic (`ar`, right-to-left). Structure so Farsi (`fa`) and others can be added.
- Knowledge base: 30 to 50 official pages.

## 2. Principles (apply to every feature)

1. **Grounded:** answers only from retrieved official passages, with citations and "last checked" dates.
2. **Honest:** "I don't know from official sources" is a valid answer and must offer a person.
3. **Information, not advice:** case-specific immigration questions go to handoff.
4. **Curated facts:** roadmap steps come from human-written templates, never generated by the model.
5. **Private:** minimal data, no raw questions in logs, photos never stored, small groups suppressed.
6. **Accessible and multilingual:** voice first, plain language, RTL support, WCAG 2.1 AA basics.
7. **Low tech friendly:** works on a slow connection and a cheap phone; the phone line works with no internet.

## 5. Data model (Tiger Data)

Write migrations as plain SQL files. Tiger Cloud services include TimescaleDB; enable `vector` (and check whether
`vectorscale` is available; optional). Use the current TimescaleDB syntax from the docs.

### 5.1 Tables

| Table | Kind | Columns (main) |
|---|---|---|
| `sources` | regular | `id`, `url` (unique), `title`, `jurisdiction` (`federal`/`ontario`/`ottawa`), `language`, `topics` (text[]), `last_fetched_at`, `last_changed_at`, `content_hash`, `active` |
| `source_chunks` | regular + pgvector | `id`, `source_id`, `chunk_index`, `heading_path`, `text`, `language`, `embedding vector(EMBEDDING_DIM)`, `token_count` |
| `source_snapshots` | **hypertable** on `time` | `time`, `source_id`, `content_hash`, `changed` (bool) |
| `step_templates` | regular (seeded from JSON) | `id` (slug), `title_en`, `summary_en`, `conditions` (jsonb), `documents` (jsonb), `where_en`, `timing` (jsonb), `source_url`, `topic`, `order_hint`, `reviewed` (bool) |
| `profiles` | regular | `id` (uuid), `auth0_sub` (nullable), `status`, `arrival_date`, `city`, `province`, `has_children`, `has_seniors`, `languages` (text[]), `preferred_language`, `needs` (text[]), `created_at` |
| `user_steps` | regular | `id`, `profile_id`, `template_id`, `status` (`todo`/`done`/`skipped`), `due_date`, `completed_at` |
| `request_log` | **hypertable** on `time` | `time`, `channel` (`web`/`voice_web`/`phone`), `language`, `topic`, `status_category`, `region`, `answered` (bool), `handed_off` (bool), `scam_flag` (bool), `clarity` (smallint null: 1 up, -1 down), `source_ids` (int[]), `gap_summary` (text null), `is_sample` (bool default false) |
| `handoffs` | regular | `id`, `created_at`, `language`, `topic`, `summary`, `contact_method`, `contact_value` (encrypted or plain for MVP with a TODO), `preferred_time`, `consent` (bool, must be true), `status` (`new`/`in_progress`/`resolved`), `assigned_to`, `urgency` |
| `reminders` | regular | `id`, `profile_id`, `user_step_id`, `send_at`, `channel`, `sent_at` |
| `processing_times` | **hypertable** on `time` | `time`, `application_type`, `days` (stretch goal) |

Indexes: HNSW (or DiskANN if vectorscale exists) on `source_chunks.embedding` with cosine distance;
btree on `source_chunks(source_id)`, `request_log(topic, time desc)`.

### 5.2 Continuous aggregates
- `request_log_daily`: `time_bucket('1 day')`, grouped by `topic`, `language`, `region`, `channel`, `is_sample`;
  columns `total`, `answered`, `handed_off`, `scam_flags`, `clarity_up`, `clarity_down`.
- `request_log_weekly`: same with `time_bucket('1 week')`.
- Enable real-time aggregation so new rows appear immediately in the demo, and add refresh policies.
- Add a retention policy on `request_log` using `REQUEST_LOG_RETENTION_DAYS`.

### 5.3 Topic taxonomy (`topics.json`)
A fixed list so aggregates are clean, for example: `health_card`, `sin`, `banking`, `housing`, `taxes_benefits`,
`child_benefit`, `school_registration`, `language_classes`, `employment`, `credentials`, `drivers_licence`,
`transit`, `immigration_status`, `work_permit`, `study_permit`, `sponsorship`, `citizenship`, `legal_rights`,
`scams`, `emergency`, `other`. Each topic has labels in `en`, `fr`, `ar`.

## 6. Ingestion pipeline (`ingestion/`)

- `sources.yaml` lists pages: `url`, `jurisdiction`, `topics`, `language`, `verified` (bool).
  **Do not invent URLs.** Include only URLs you are highly confident exist, all with `verified: false`, plus
  commented placeholders for topics the team must fill in. The script must report every URL that fails.
- `ingest.py`:
  1. Fetch each page with httpx (timeout, retries, polite user agent, 1 request per second).
  2. Extract main content with BeautifulSoup (drop nav, header, footer, scripts). Keep headings.
  3. Compute a content hash. If unchanged since last fetch, record a snapshot with `changed=false` and skip.
  4. If changed or new: chunk (about 500 to 800 tokens, 10 to 15% overlap, split on headings first, keep
     `heading_path`), embed with Gemini (`EMBEDDING_DIM`, document task type), replace that source's chunks
     in one transaction, record a snapshot with `changed=true`, update `last_changed_at`.
  5. Print a summary: pages fetched, changed, failed, chunks written.
- Runnable as a CLI and callable from the backend scheduler (daily) and `POST /api/admin/ingest`.

## 7. Backend services

### 7.1 Gemini wrapper (`services/gemini.py`)
- Use the `google-genai` SDK. One place for retries, timeouts, and logging of latency (not content).
- Structured outputs via response schemas (Pydantic models) for classification, letters, scam checks, summaries.
- Low temperature for factual tasks.

### 7.2 Classifier (`services/classifier.py`)
One structured call per question returning:
```
{ "language": "ar", "topic": "health_card", "is_case_specific": false,
  "case_specific_reason": null, "urgency": "normal" | "high" | "emergency",
  "possible_scam": false, "search_query_en": "..." }
```
- `is_case_specific` is true when the person asks what they personally should decide in an immigration matter
  (which application, whether to sponsor, how to handle a refusal, deportation, hearings).
- `urgency: emergency` (danger, violence, medical emergency) → the response must tell them to call 911 first.
- `search_query_en` is an English rewrite used for retrieval (the knowledge base is mostly English and French).

### 7.3 Retrieval (`services/retrieval.py`)
- Embed the query (query task type), cosine search top 8, filter by jurisdiction in (`federal`, the user's
  province, the user's city), optional topic boost. Return chunks with source title, url, last_fetched_at.
- Drop chunks below a similarity threshold (configurable). If nothing remains → unanswered.

### 7.4 Grounded answer (`services/answer.py`)
Prompt (store in `prompts/answer.md`):

```
You are Arrive, a helper for newcomers to Canada.
Answer ONLY using the official passages below. Do not use any other knowledge.
If the passages do not contain the answer, reply with "not_found": true.
Write in {language}, at a grade 6 reading level, in short sentences.
Give the direct answer first, then up to 3 short steps if useful.
Never tell the person what they personally should decide about an immigration matter.
Cite the passages you used by their ids.
Passages:
{passages with ids, titles, urls}
Person's situation (may help choose relevant passages): {status, province, city, family}
Question: {question}
```
Response schema: `{ "not_found": bool, "answer": str, "steps": [str], "citations": [chunk_id], "follow_ups": [str] }`.
- Validate that every cited id was in the passages; drop invalid ones; if no valid citation, treat as not found.
- Not found → friendly message in the user's language + offer handoff + log `gap_summary` (see 7.9).

### 7.5 Roadmap engine (`services/roadmap.py`)
- Load `step_templates.json` into `step_templates` on startup (upsert).
- Match templates whose `conditions` fit the profile (status, province, city, has_children, has_seniors,
  weeks since arrival). Compute due dates from `timing` (for example "within 2 weeks of arrival").
- Order by `order_hint` and due date. Mark the first incomplete step as "now".
- Gemini only translates and slightly personalizes the wording; it never adds, removes or changes requirements.
  Cache translations per template and language.
- **Draft the templates** for the two MVP statuses (about 10 to 14 steps each: SIN, bank account, phone plan,
  settlement agency registration, health card, school registration, language classes, driver's licence,
  first tax return, child benefit, transit pass, library card, and for students work-hour rules and permit
  expiry awareness). Every template has `reviewed: false`, a `source_url` taken only from `sources.yaml`, and
  `[VERIFY: ...]` markers on any document list or timing you are not certain about.

### 7.6 Letter decoder (`services/letters.py`)
- Accept JPEG/PNG/HEIC/PDF up to 10 MB. Read into memory only; never write to disk or DB; discard after the call.
- Gemini vision, structured output:
  `{ "sender": str, "sender_confidence": "high"|"medium"|"low", "what_it_means": str, "action_needed": bool,
     "deadline": str|null, "steps": [str], "amount_owed": str|null, "looks_suspicious": bool,
     "suspicious_reasons": [str] }` in the user's language.
- If `looks_suspicious`, link to the scam check. Always add the "information, not legal or tax advice" note.
- Log only topic, language, channel to `request_log` (never letter content).

### 7.7 Scam check (`services/scam.py`)
- Retrieve passages from scam and fraud guidance sources, then structured output:
  `{ "verdict": "likely_scam"|"likely_real"|"unsure", "reasons": [str], "what_to_do": [str], "citations": [chunk_id] }`.
- Always include how to report to the Canadian Anti-Fraud Centre (URL from `sources.yaml`, `[VERIFY]`).

### 7.8 Handoff (`services/handoff.py`)
- Created only with `consent: true`. Gemini writes a short summary for the worker (English, plus the person's
  language), without adding facts the person did not say.
- Urgency from the classifier. Log `handed_off=true` in `request_log`.

### 7.9 Anonymized request log (`services/request_log.py`, `services/privacy.py`)
- One row per interaction. Never store raw question text, names, phone numbers, emails, addresses, dates of
  birth, or document numbers.
- `region` is city level only.
- `gap_summary` (only when unanswered): a short, generic description of what was asked, written by Gemini with
  instructions to remove all personal details (for example "health card coverage for refugee children").
  Run a regex PII scrub after the model as a second layer.
- `clarity` is updated by `POST /api/feedback`.

### 7.10 Insights (`services/insights.py`)
Queries against the continuous aggregates:
- top topics this week vs last week with percentage change and spike flag
- language demand by week and region
- channel mix (web, web voice, phone)
- answered rate, handoff rate, scam flags
- knowledge gaps: most common `gap_summary` themes (group similar ones with a Gemini clustering call, cached)
- confusing sources: sources with the most clarity-down or follow-up questions
- **Suppression:** any group with fewer than `INSIGHTS_MIN_GROUP_SIZE` records returns `"<5"` instead of a number.
- `POST /api/insights/brief`: Gemini writes a one-page needs brief from aggregated numbers only.
- Responses include `has_sample_data: bool` so the UI can show a "Sample data" badge.

### 7.11 Voice
- `GET /api/voice/session`: returns what the web client needs to start a conversation with the ElevenLabs agent
  (signed URL or conversation token for a private agent; check current ElevenLabs docs).
- `POST /api/voice/tools/ask`, `/roadmap`, `/handoff`, `/scam-check`: server tools the ElevenLabs agent calls.
  Require header `X-Arrive-Secret: VOICE_TOOL_SECRET`. Return short, speakable text (under about 60 words) plus
  citations. Log with `channel=phone` or `voice_web` (passed by the agent as a tool parameter).
- Write `docs/ELEVENLABS_AGENT.md`: the agent system prompt, first message, language settings, tool definitions
  (names, descriptions, parameters, URLs, headers), and the Twilio phone number import steps. The agent prompt
  must repeat the principles: official sources only through the tools, no personal immigration advice, offer a
  person, keep answers short, confirm understanding, and tell people in danger to call 911.

### 7.12 TTS
- `POST /api/tts` with `{ text, language }` → audio (mp3) from ElevenLabs using the multilingual model.
  Cache by hash of text + voice to save credits. Limit text length.

### 7.13 Cross-cutting
- Rate limiting per IP on public endpoints (for example slowapi), stricter on letters and TTS.
- Input validation with Pydantic; max lengths on all text fields.
- CORS from `CORS_ORIGINS` only.
- `GET /api/health` checks DB connectivity.
- Structured logging without user content.
- Errors return friendly, translatable error codes, not stack traces.

## 9. Frontend

### 9.1 Design system (from our approved mockup)
- Colors: ground `#F6F3EC`, surface `#FFFFFF`, ink `#1C2321`, muted text `#5B635F`, border `#E2DDD2`,
  primary teal `#0E5E57` (hover `#0A4540`), teal light `#E3EFEC`, amber light `#FBEEDC` with text `#6B3A0E`
  (deadlines, handoffs), danger light `#FBEAE6` with text `#8E2A1D` (scams), dark sidebar `#123B37`.
- Fonts: display **Fraunces** (headings), body **Atkinson Hyperlegible** (chosen for low-vision legibility).
  Arabic: **Noto Naskh Arabic** or **IBM Plex Sans Arabic** for `ar` and `fa`. Load with `next/font`.
- Rounded cards (14 to 18px radius), generous spacing, one primary action per screen, stroke icons (lucide-react).
- No gradients, no emoji as icons, no decorative animation. Respect `prefers-reduced-motion`.

### 9.4 Accessibility and i18n requirements
- `dir="rtl"` and `lang` set on `<html>` per locale; use logical CSS (`ms-`, `me-`, `ps-`, `pe-`, `start`, `end`)
  so layouts flip correctly. Icons with direction (arrows) flip in RTL.
- WCAG 2.1 AA: contrast 4.5:1 for text, 44px targets, visible focus rings, skip link, semantic landmarks,
  labels on all inputs, `aria-live="polite"` for new answers and status ("Listening", "Thinking", "Speaking").
- Full keyboard use, including the voice button (space/enter to start and stop).
- All UI strings in `messages/*.json`. Draft `fr` and `ar` translations and mark the files
  `"_review": "needs native speaker review"`.
- Answers come back already in the chosen language from the backend.
- Low-bandwidth: no large images, system-light pages, lazy-load charts; roadmap cached for offline viewing
  (service worker or simple cache) as a stretch goal.
- Profile id and accessibility settings stored in `localStorage`; "Delete my data" in settings clears them and
  calls the API to delete the profile.

### 9.5 Voice in the web app
- Use `@elevenlabs/react` (`useConversation`) with the session from `/api/voice/session`.
- Clear states with text and icon, not color alone: idle, connecting, listening, thinking, speaking, ended.
- Show a live transcript. Ask for microphone permission with an explanation first. Fallback to text if denied.
